# Observability — playbook-stage tool calls don't reach audit.jsonl

Status: **OPEN** (wayfinder ticket, OBS-002 — GitHub issue #193)

## Question

`audit.jsonl` claims to be "an audit trail of tool calls" (SOUL.md system-state map; `query_audit` reads it) — but tool calls executed *inside a scheduled playbook run* never land there. If a run does something expensive, destructive, or surprising, the main audit trail is silent about it.

## Evidence (2026-08-15, live VPS archaeology)

| Check | Result |
|---|---|
| Images created in `/tmp/mino/results/images/` since 2026-08-08 | **61 files** (instagram/facebook/threads daily playbooks) |
| `generate_image` tool_name entries in `audit.jsonl` since 2026-08-08 | **0** (last real call 2026-08-07; 26 all-time) |
| Aug-14 instagram run (`scheduled-instagram-daily-capability`, session in traces) | Wrote 3 images + `view_image` critiques — image filename `1786673103894730544.png` found **nowhere** in `audit.jsonl` |
| Where the evidence actually lives | `traces/2026-08-*.jsonl` (schema/turn records + tool outputs) and the run's own `output/*.md` stage reports |

The Aug-14 images were generated by Cloudflare `@cf/black-forest-labs/flux-1-schnell` per trace + run-log provenance — the answer "which model made this image" is only answerable by trace archaeology, not by `query_audit`.

## Root cause hypothesis

The main audit (`Core`-level tool dispatch) covers conversational turns; playbook runs execute through `playbook_workspace.go`'s own loop (per `docs/playbooks-design.md` — "execute through the canonical Mino loop"), whose inner tool calls are attributed to the run for write-verification but apparently not emitted to the shared audit stream. Needs confirmation in code.

## Scope

1. Confirm the emission gap in code: find where `audit.go` writes tool entries vs where `playbook_workspace.go` dispatches stage tools.
2. Emit playbook-stage tool calls to `audit.jsonl` with the playbook/run attribution already present in the run's internal records (playbook name, run ID, stage), so `query_audit` answers "what did the 08:30 threads run actually do" from the audit alone.
3. Keep the run's own write-attributed verification unchanged — this is additive visibility, not a rework of stage evidence.

## Acceptance criteria

- [ ] A scheduled playbook run's tool calls (at minimum: generate_image, bash, and the MCP/composio tools) appear in `audit.jsonl` with playbook/run/stage context
- [ ] `query_audit` can answer "which model generated images since date X" without reading traces
- [ ] Playbook write-attribution verification still passes (existing `playbook_test.go` suite green)

## Out of scope

- New metrics infrastructure (the trace journal + audit stay the surface — OBS-001 principle)
- Backfilling historical audit entries (the gap is forward-fixed)
- Changing what traces capture
